## Implementation sequence

1. Identify technician and manager assignment roles and any existing staffing tables.
2. Build assignment UI against an approved adapter, using available workload and technician list.
3. Ensure only authorised staff can assign/change workloads.
4. Handle unavailable staff, concurrent updates and unsuccessful assignments without losing form state.

## Verification scenarios

- [ ] Unauthorized user cannot reassign a job through UI or API.
- [ ] Assignment of missing/inactive staff is rejected or clearly surfaced.

## Constraints and dependencies

- Test one complete staff action against fixtures first; confirm which current pages use live services versus demonstration data.
- Use a typed fixture or mock adapter when another team has not yet delivered its backend; do not block all progress on a sibling issue.
- Obtain lead approval for changed API contracts, identity permissions, database migrations, protected customer data, and deployment controls.
- Keep `pnpm` workflow and TypeScript strict conventions; preserve tenant isolation and private/internal visibility.
- This task is not an authorization to introduce a new product feature unrelated to its stated outcome.
