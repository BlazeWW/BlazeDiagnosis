## Outcome

Deliver **production authentication validation** as a bounded, independently reviewable change or assessment. Expected task-specific evidence: **Authentication flow diagram, tests and production configuration checklist**. Begin with the code as it exists today; confirm whether a function is already implemented, partially implemented, or mock-backed before adding code.

## Implementation sequence

1. Trace authentication from login/cookie or bearer token through token verification and user context.
2. Check logout, expiration, invalid signature, missing secret and provider configuration handling.
3. Verify that development fallback cannot be enabled on production deployments.
4. Add targeted session tests without putting provider secrets into fixtures.

## Verification scenarios

- [ ] No token and expired or invalid token are rejected in production-like mode.
- [ ] Valid user cannot silently gain platform-admin access or another tenant membership.

## Constraints and dependencies

- Read AGENTS.md, the auth/tenant architecture, and the API contract before editing security or schema code.
- Use a typed fixture or mock adapter when another team has not yet delivered its backend; do not block all progress on a sibling issue.
- Obtain lead approval for changed API contracts, identity permissions, database migrations, protected customer data, and deployment controls.
- Keep `pnpm` workflow and TypeScript strict conventions; preserve tenant isolation and private/internal visibility.
- This task is not an authorization to introduce a new product feature unrelated to its stated outcome.
