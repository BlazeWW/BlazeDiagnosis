## Implementation sequence

1. Trace parts request creation through station API, tenant scope and supplier visibility.
2. Persist request and line items with correct job/vehicle ownership.
3. Validate requested quantities and protect against duplicated submissions.
4. Test request retrieval, forbidden tenant and supplier boundary cases.

## Verification scenarios

- [ ] Valid request survives reload and is visible only to intended authorised suppliers.
- [ ] Invalid quantity and cross-tenant job references are rejected.

## Constraints and dependencies

- Keep supplier commercial data separate from customer and competing-supplier data; never claim a weak fitment match is certain.
- Use a typed fixture or mock adapter when another team has not yet delivered its backend; do not block all progress on a sibling issue.
- Obtain lead approval for changed API contracts, identity permissions, database migrations, protected customer data, and deployment controls.
- Keep `pnpm` workflow and TypeScript strict conventions; preserve tenant isolation and private/internal visibility.
- This task is not an authorization to introduce a new product feature unrelated to its stated outcome.
